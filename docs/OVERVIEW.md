# Easy RPA 使用指南

## 创建与运行

1. 在 Studio 新建流程，添加节点与连线；也可向 AI 助手提供目标网址和任务要求。
2. 配置输入变量。账号、密码和 Token 在输入变量面板填写，不放进对话或节点文本。
3. 选择执行方式并运行，在任务记录中查看日志、输出和失败截图。
4. 需要定时执行或被子流程调用时，先发布流程，再配置调度或调用节点。

| 执行方式 | 适用场景 |
| --- | --- |
| 独立浏览器 | 使用应用管理的浏览器 Profile，适合重复执行和定时任务 |
| 当前 Chrome | 复用真实浏览器登录态，适合企业 SSO 或需要预先完成验证的站点 |

使用当前 Chrome 时，在设置页获取扩展安装入口，加载后确认连接在线，再从流程顶部运行菜单切换。更新扩展后需在 Chrome 扩展管理页重新加载。

## 流程能力

| 类别 | 常用能力 |
| --- | --- |
| 浏览器 | 打开页面、点击、填写、选择、等待、截图、标签页、表格提取和分页 |
| 控制流 | 条件分支、遍历、条件循环、异常处理和子流程 |
| 数据与变量 | 变量赋值、JSON、正则、列表、数学和类型转换 |
| 文件与 Excel | 读写、复制、压缩、表格筛选与导出 |
| 请求与脚本 | HTTP 请求、Python、JavaScript、Shell 和 WebSocket |

遍历和条件循环的出边分为 `body`（循环体）与 `exit`（退出）。等待页面变化优先使用等待节点；固定延时不能保证数据已刷新。

提取表格时将默认的 `text` 模式改为 `table` 并定位数据行，避免把按钮、页码等 UI 内容抓入结果。`outputSchema` 可声明输出字段与表头别名，缺少必需字段会报错。

## 分页采集

使用 `browser.paginateNext` 累计完整分页结果，总页数可以变化，无需额外配置末页标记。

| 配置 | 用法 |
| --- | --- |
| 点击翻页 | `selector` 指向下一页控件，`targetSelector` 指向本页数据 |
| URL 翻页 | `urlTemplate` 包含 `${page}`，如 `https://example.com/list?p=${page}`；`selector` 可选，仅用于检查下一页禁用状态 |
| 起始页与步长 | URL 模式的 `startPage`、`pageStep` 默认均为 1；offset 分页按实际地址规律设置 |
| 页数安全上限 | `maxIterations` 默认 20，可填正整数或 `${var.max_pages}`；包含起始页，不是实际总页数 |
| 等待 | `timeoutMs` 控制每页稳定等待预算，`delayMs` 是翻页后的额外延时 |
| 输出 | `outputVariable` 保存累计数据，`pageCountVariable` 保存有数据的页数 |

下一页控件可见且禁用时结束。URL 模式还可在至少采到两页数据后，通过实际导航回到上一页且内容稳定相同确认结束；仅靠回跳判断时，安全上限需留出下一次导航的空间。

例如实际有 3 页，上限设为 10，仍可在第 3 页确认末页后结束。达到上限但未确认结束会失败；空页、重复内容或下一页消失都不能单独证明完整。分页节点不能忽略失败，也不会自动重跑。

翻页失败时，先检查失败页的行选择器、下一页控件和实际地址；确认确有慢加载后再调整等待时间。修复后从流程起点重新运行。跨页业务记录如需去重，应按业务键另行处理。

## 变量与脚本

节点字段使用 `${var.name}` 引用变量。每次运行还提供以下内置变量：

| 变量 | 用途 |
| --- | --- |
| `run_timestamp` | 本次运行时间标识 |
| `flow_slug` | 已保存流程的 ID，临时流程回退为名称标识 |
| `output_dir` | 本次运行的产物目录 |
| `output_prefix` | 产物目录下带时间戳的文件名前缀 |

Python 脚本通过 `_vars['name']` 读取变量。JavaScript 脚本运行在本地 Node.js，不能直接访问网页 `document` 或 `window`。可生成的文件格式取决于运行环境已安装的库。

部分流程支持导出独立 Scrapling 脚本；包含 `browser.paginateNext` 的流程不支持该导出。

## AI 助手

助手可以检查页面、创建和修改流程、诊断失败、按要求运行并检查输出。仅要求审查或修复时，不会自动运行。节点运行成功不等于业务验收通过，应检查输出是否满足采集范围、筛选条件和交付要求。

模型与 API 连接在设置页配置。复杂页面通常需要结合真实页面和运行结果调整；当前流程节点不提供模型驱动的总结、翻译等语义加工。

## 使用边界与数据

- 自动化范围是网页，不覆盖原生桌面 GUI；支持 iframe 和 open Shadow DOM，不支持 closed Shadow DOM。
- 验证码、短信码、扫码及授权登录需先在扩展浏览器完成。运行时遇到验证会失败并保留现场，不会暂停等待输入。
- 扩展中的敏感动作可启用执行前确认；当前 Chrome 需保持在线，不建议作为无人值守主路径。
- 运行产物可在任务记录中查看，本地存储位置见 [数据目录](TECHNICAL.md#数据目录)。访问目标网站和调用 AI 供应商需要网络，相关对话和工具证据会发送给所配置的供应商。
